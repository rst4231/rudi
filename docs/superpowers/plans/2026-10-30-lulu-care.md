# Lulu care blocks

Goal: Four shared blocks approved by the user: weight history, current nutrition, vaccinations/parasite prevention, veterinarian prescriptions and intake marks.
Base: production v4.378 (7952bce5cd07fd4ba5b4143943dd92e9ca3b3b2c).
Architecture: dedicated per-record care store via existing authenticated Lulu endpoint. Separate public care module, existing offline outbox, existing dog-themed profile. No new serverless function or automatic notifications.
Records: weight (kg, measured date), goals (optional vet-supplied target kg), nutrition (food, grams/day, treats, change date, note), prevention (vaccine/parasite, product, administered date, optional next date, note), prescription (name, verbatim dose/schedule, start/end, doctor, note, completed), intake (prescriptionId, timestamp).
Constraints: Shared between Rustam and Diana; blank initial values; no inferred doses, diagnoses or automatic preventive intervals. Care records survive month changes; walk retention unchanged. No deployment before a final user confirmation.
Implementation decisions: Per-record revisions prevent stale edits and independent records remain independent; stable IDs make retries idempotent; deletion uses tombstones. Offline SET commands coalesce by record preserving original revision. Conflicts remain visible and can be explicitly discarded to show server data. Intake marks are individual events rather than one ambiguous daily checkbox.
